# Ultimate setup for the provider portal

- **Worktree location:** Ultimate's checkouts live next to rwt's in the repo's own `.worktrees/`, named `ult-<hash>-<conversation id>` (the lander's is `ult-lander-<hash>`), via `isolates.worktree.path`.
- **Worktree setup** (`worktree-setup.sh`): each Ultimate worktree copies `deps`, `_build` and `assets/node_modules` from your checkout (APFS copy-on-write) and copies `.env`. It then gives the worktree its own `GIT_WORKTREE=ult_<id>`, so it gets separate `rx_*_ult_<id>` databases, and its own ports: `PORT=20000 + id%1000*10`, with `LIVE_DEBUGGER_PORT` and `RX_METRICS_PORT` on the next two. Finally it runs `mix deps.get` and compiles dev and test. Test databases are created by `mix test`; dev databases only when a branch runs `mix ecto.setup`.
- **Agents** (`agents/`): additions to the built-in coordinator, worker and designer. They run `mix` through `mise exec --`, so the worktree's `.env` loads. Coordinators ship through GitHub pull requests on `sm-<topic>` branches against `main`, never by merging into local `main`. The review team (`reviewer-*`) covers correctness, simplicity, architecture and security; `reviewer-security` applies Cloudflare's security-audit skill in guidance mode when a range touches auth. `reviewer-correctness` and `reviewer-security` are overlays (`addTools: []`) holding only this portal's focus: their generic method lives once in `~/.ultimate/agents/` (dotfiles `home/.ultimate/agents/`).
- **Pi** (`../.pi/agents/`, linked into the gitignored `.pi/agents/`): `reviewer-simplicity` and `reviewer-architecture` wrappers that read these files, so pi and Ultimate share one text. Pi's global `reviewer-correctness`, `reviewer-security` and `worker` read the generic file plus this folder's addition themselves. Pi discovers project agents from the session's cwd, so the wrappers apply in the main checkout; from an rwt worktree only the global reviewers run.
- **Strive-wide rules** (`~/code/work/strive/AGENTS.md`, read by Pi and Ultimate in every strive repo): commits and PRs never name the harness (git config `config.strive` switches the `Ultimate-Conversation` trailer off and a pre-push check enforces it), screenshots go inline via `gh pr create --attach`, and auth changes get the security audit before the PR opens.
