# Home Manager configuration

This file covers the user-level layer: how program modules are discovered, package and app composition, per-tool config conventions, and an index of the tools managed under `nix/home/common/programs/`. Apply with `just home`.

## Module auto-import

`nix/home/common/default.nix` auto-imports every `nix/home/common/programs/<tool>/` directory that contains a `default.nix`, so the layout stays one directory per tool instead of a hand-maintained import list.

The auto-import filters by directory shape; `nix/home/common/default.nix` still imports `inputs.worktrunk.homeModules.default` when the optional `worktrunk` flake input exists, though the local worktrunk program module is removed (wave-1 mise flip) so nothing enables it. Alongside the program modules it imports `lib.nix`, `packages.nix`, `services.nix`, and `accounts.nix`. Pi is installed as a normal Home Manager package from its local module, not through `pi-nix`.

`nix/home/common/default.nix` also sets `home.sessionPath`, session variables, the `~/bin` link, an `.editorconfig`, and out-of-store symlinks for iCloud and Proton drives. It enables `targets.darwin.copyApps` (not `linkApps`) so GUI apps work with Spotlight, and runs `lib.mega.mkAppActivation` over `config.mega.customApps`.

## Package and app composition

The 2026-08 first mise-only wave removed shared Home Manager apps and packages covered by verified mise or Homebrew sources.

IINA, Inkscape, Slack, Zoom, OBS beta, Tidewave GUI/CLI, k9s, Rust, Difftastic, Python, Lua, and the remaining shared fonts moved to mise declarations. Tidewave's GUI uses the GitHub DMG postinstall pattern while its CLI remains the Aqua tool. Fnox and mise tasks own dependent config/activation behavior as each module retires.

Local inference uses llama.cpp, not Ollama. The service is mise-owned on both hosts: launchd agent `dev.mise.com.megadots.llama-cpp` runs `mise/scripts/llama-server-launchd` (the `nix/home/common/programs/llama-cpp-local/` module still defines the nix options but is no longer enabled anywhere; running both fought over port 18080). The wrapper launches the absolute `llama-cpp/latest/llama-server` binary so unattended startup never enters a mise shim or fnox resolution. `config/llama-cpp/models.ini` supplies router overrides: `nomic-embed` runs in embedding mode with a 2048-token context and mean pooling, exposing 768-dimensional OpenAI-compatible embeddings at `http://127.0.0.1:18080/v1/embeddings`. `nix/home/common/programs/ollama/` stays an inert compatibility module. `bin/llm-pull` defaults to the `llamacpp` backend and creates GGUF alias symlinks (`qwen3.6.gguf`, `deepseek14b.gguf`, `gemma4.gguf`, `nomic-embed.gguf`) so the router exposes stable model IDs.

## Per-tool config conventions

Tool-specific dotfiles and XDG links live beside their owning Home Manager module rather than in a central config block.

Example: Yazi plugins under `yazi/`. Tools flipped to mise ownership (git, jj, bat, eza, ripgrep, fd, karabiner, surfingkeys, starship, fzf, zoxide, atuin, espanso, kitty) live under `config/<tool>/` (or fish `conf.d/` hooks) and are linked by `[dotfiles]` instead. Apps that need live-editable config use out-of-store symlinks into the repo `config/` tree (see [[architecture#Out-of-store config symlinks]]). VS Code is not installed; Neovim is the editor path.

Standalone project templates live under `config/mise/tmpls/`. `shopify.toml` bootstraps Shopify theme work with Node LTS, Shopify CLI, local npm editor dependencies, Biome for supported web files, Theme Check, Liquid Prettier, `shopify.theme.toml` environments, and local dev tasks. `elixir/mise.local.toml` loads `.env` and `.env.local` with `tools = true` and `redact = true` so `mise run` tasks, including tmux service windows, see the same local secrets and dev toggles as direnv shells while those files stay untracked. Its `expert = "0.1.10"` tool uses mise's official `expert` registry key (`aqua:expert-lsp/expert`) instead of the former upstream namespace and keeps project setup reproducible with the current release pinned. The elixir template's shared per-repo postgres resolves `PGPORT` deterministically via `scripts/pg-port.sh` (`5433 + cksum(repo-name) % 1000`, keyed to the main repo root via git-common-dir so every worktree of a repo agrees while different repos avoid colliding on 5432; pre-set `PGPORT` wins); `setup-db.sh` re-syncs the cluster's `postgresql.conf` port on every run and `start-db.sh` restarts a cluster caught listening on a stale port. Routine `mise run setup` and Worktrunk service startup only create databases and never drop/reset them; destructive dev/test resets require the interactive `mise run db:reset` task. `bootstrap:pi` writes only a marker-delimited generated block in `.pi/APPEND_SYSTEM.md` and merges Tidewave into `.pi/mcp.json`, preserving project-owned `AGENTS.md`, other Pi guidance, and MCP servers; it rejects symlinked targets rather than replacing or following them. The Tidewave entry stores the literal `${PHX_PORT}` URL - pi interpolates env vars in MCP server URLs at connect time (missing variables fail fast), so no port is ever baked into `.pi/mcp.json`. During mise's pre-PATH config evaluation, `phx-port.sh` resolves `:erlang.phash2/2` through the globally managed Elixir with auto-install disabled; this prevents the exported `PHX_PORT` and Tidewave URL from collapsing to the base port `4000`.

Templates use a stub-and-include delivery model: the generated `<repo>/.config/mise.toml` is a small stub whose tasks load from the dotfiles template's `tasks.toml` via `[task_config] includes`, whose repo-keyed env (HOST, shared-postgres `PG_ROOT`/`PGHOST`/`PGPORT`/`PG_LOG`/`PGDATA`) is sourced from the template's `env.sh` via `[env] _.source`, and whose scripts execute from `config/mise/tmpls/<stack>/scripts/` directly — nothing behavioral is copied, so template edits apply to every consuming repo and worktree immediately. Worktree-sensitive vars (`GIT_WORKTREE`, `PHX_PORT`) stay in the stub as `{{ cwd }}`-anchored Tera execs because mise runs `_.source` with cwd = config root and nested worktrees load the ancestor stub first — only `cwd` resolves against the checkout being entered. Included task files use top-level task names (no `[tasks.]` wrapper); `[tools]`, `[deps]`, `min_version`, and `[env]` cannot ride `task_config.includes` and stay in the stub. Project overrides go in the stub or a project `mise.local.toml` (e.g. one worktree pins `TICKETS_DIR`). Global `gen:<template>` mise tasks (duplicated in both the nix `globalConfig` and the mise-twin `config.toml`) run `bin/mise-tmpl-gen`, which generates the stub to `<target>/.config/mise.toml` idempotently: byte-identical destinations are untouched, differing ones replaced, parent `.config/` is created with a `.metadata_never_index` Spotlight opt-out marker, and mise configs are `mise trust`ed. `mise-tmpl-gen --check <lang> [target]` reports drift against the template, flags stale legacy `.config/scripts/` copies, lists unmanaged `.config/` content as notes, and exits nonzero when regeneration or cleanup is needed. The former `wt.<lang>` mode (generated `.config/wt.toml` Worktrunk hook configs) is removed along with the template `wt.local.toml` and `wt-services-cmd.sh` files; the v2 flow runs Worktrunk with `--no-hooks` and projects carry no Worktrunk config. Both global Git excludes ignore project-level `.config/` directories (and `.worktreeinclude`) so generated configs stay untracked by default.

The retained-Worktrunk migration has a contract-first fixture suite under `.local_scripts/worktree-contracts/` (local-only, untracked; formerly `tests/worktree/`). `run.sh self-test` validates temporary Git repositories, published schema-2-shaped backend fixtures, closed noninteractive stdin, and a unique isolated tmux socket. `run.sh contract` exercises the versioned `wt`/deterministic `ftm` contract; all 39 grouped cases pass after the presentation cutover. `cases.tsv` maps migration requirements to executable test IDs. The harness uses inert Worktrunk, mise, Pi, and service shims; it never runs project setup, services, or databases. Its successful removal fixture matches Worktrunk 0.76.0's one-element JSON array and deletes the fixture's local worktree/ref so the wrapper's post-removal checks run against real resulting state.

Phase 2 adds the common project contract without activating the new runtime flow. Generated Elixir and Shopify configs expose blocking `dev:setup` and foreground `dev:services` tasks while old task names and Worktrunk hooks remain available. Both setup tasks install the declared toolchain first. Elixir setup refreshes Pi/MCP config on every call, gates heavier non-destructive setup with `.local/state/setup-complete`, and preserves a caller-supplied `GIT_WORKTREE`; the gated `setup.sh` creates the dev and test databases then runs `ecto.migrate` for both (fresh per-worktree databases are empty after create, and services crash on missing tables without it); its services task starts or reuses the shared per-repository PostgreSQL cluster, then runs `dev-services.sh`, which titles the tmux window `services-<port>` (port from `phx-port.sh`, `$PHX_PORT` fallback; the running-server probe only matches beams whose command line runs `phx.server` and only accepts listening ports in the deterministic 4000–4999 range, so pi-elixir project VMs and `mix test` beams sharing the checkout cwd cannot misreport an ephemeral distribution port), mirrors pane output to `.local/log/services.log` for the `logs`/`logs:follow` tasks, and execs the worktree Phoenix server. Shopify setup runs bootstrap before a source/output-tracked npm install; its services task runs Shopify theme development in the foreground. Task definitions live in each template's `tasks.toml` (consumed via `[task_config] includes`) and scripts run from the template's `scripts/` directory; `mise-tmpl-gen <stack>` generates only the small `.config/mise.toml` stub. Generation also additively merges the template's copy-ignored allowlist into the project's `.worktreeinclude` (template `worktreeinclude` file when present, else the `.config/` + `.env` + `.envrc` trio) and `--check` reports missing entries; the elixir template lists `deps/` and `_build/` so Worktrunk's `wt step copy-ignored` (reflink/clonefile — copy-on-write on APFS) seeds the Mix caches into every new worktree before blocking `dev:setup`, whose `mix deps.get`/compile validate the seeded cache instead of rebuilding from scratch.

Phase 3 adds the deterministic session layer without changing picker or shell defaults. `bin/wt-lock-lib` is the single shared mutation-lock primitive (sourced by `wt` and `ftm`): `mkdir`-based lock dirs under `<git-common-dir>/wt-wrapper/locks/` (`repository` acquired before `worktree-<id>`), owner metadata with pid plus process start time (pid-reuse guard), lease tokens that name a held repository+worktree pair, bounded waits (JSON/noninteractive callers never wait; interactive callers wait `FTM_LOCK_WAIT_MS`/`WT_LOCK_WAIT_MS`), and fail-closed staleness: a lock is reclaimed only when the recorded owner is provably dead, or after a >1 minute grace period when metadata never appeared; reclaim renames the dir aside before deleting so racing waiters cannot delete a fresh lock. `ftm ensure|repair|remove` are non-picker deterministic operations: `--kind worktree` acquires the shared locks (or validates an inherited `--lease` from `wt`), validates session identity read-only (tags `@ftm_kind`/`@ftm_worktree`/`@ftm_worktree_id`, or adoption of an untagged session only when session and standard-window pane cwds all equal the exact requested path), runs blocking `mise run dev:setup` when the task exists (missing is reported `missing`, failure exits 4 before any tmux mutation), then additively builds the canonical `code`/`agent`/`services` windows — extra windows/panes are preserved, one legacy `services-NNNN` window may be adopted, duplicate tagged sessions refuse with `ambiguous_session` (exit 5), and nothing is ever killed or merged. The agent and services windows are plain interactive shells whose commands are typed via `send-keys`, so the shell's job control keeps the runner (`mise`/`node`) as the foreground process for status detection and cancelling or exiting returns to the shell prompt instead of killing the pane or window. The agent shell runs `mise exec -- pi -c` when mise is available (falling back to plain `pi -c`), so pi's process env carries the project's mise `[env]` — required for env-interpolated MCP URLs like the Tidewave `${PHX_PORT}` entry; `--pi-session <uuid>` swaps `-c` for `--session <uuid>`. Typed lines stay POSIX-and-fish portable. `dev:setup` runs with `GIT_WORKTREE=<worktree-id>` exported (setup executes in ftm's process, not a pane, so tmux session env does not apply); the services window gets `remain-on-exit on` before its runner is typed and runs foreground `mise run dev:services` when the task exists (a dead pane — or a plain shell sitting where the runner should be while `dev:services` exists — reports `dead` and restarts only via `repair --restart-services`). `--kind generic` applies the same deterministic lifecycle without Git locks or worktree tags. `--format json` emits exactly one `schema_version: 1` document on stdout, never attaches, and never prompts; deterministic calls bypass snapshots and named layouts entirely. `ftm remove` snapshots the session before killing it (the `session-closed` hook only snapshots survivors) unless `--discard-snapshot` is passed; both the tmux `prefix+C-k` binding and the picker's ctrl-k action call `ftm remove`, and `detach-on-destroy off` moves any attached client to the MRU session (the former `bin/tmux-kill-session` helper is deleted).

Phase 4 completes the cutover: `bin/wt` is v2-only. Explicit `wt ensure|new|open|path|repair|prune`, `wt list --json`, any `-t`/`--target` flag, and implicit `wt TARGET` all load `bin/wt-v2-lib`; every other invocation (`switch`, `config`, `step`, plain `list`, help/version, …) execs the mise-pinned Worktrunk backend raw — no flag injection, no directive files, no auto-prune, no tmux, no parent-shell cd. The legacy wrapper path and its satellites (`wt-tmux-target`, `wt-tail-logs`, detached auto-prune, `.pi-lens.json` creation) are deleted. Implicit `wt TARGET` runs the full v2 lifecycle with the default session presentation (same as `wt open`); `-t cd` is the explicit escape hatch that runs the same lifecycle then only cds the parent shell without touching tmux; `-t window|w` builds or reuses one tagged 60/40 `wt:<id>` window (left interactive shell, right `dev:services` or shell) in the current session, falling back to cd outside tmux; `-t session|s` and `wt open` build and attach the canonical `ftm` session. `ftm` reports `presentation` as a plain string in its JSON and `wt` parses it type-safely (an object `{requested,actual}` shape is also accepted). Bare `wt repair` infers the containing checkout from the cwd (nested dirs and the primary checkout included), runs full setup, repairs the canonical session, and never cds, selects, or attaches. The primary checkout skips `copy-ignored` and unsets `GIT_WORKTREE`. The v2 path resolves `worktrunk@0.76.0` only through `MISE_AUTO_INSTALL=false mise which`, rejects wrapper recursion, verifies either released version spelling (`wt v0.76.0`) or the fixture spelling, requires schema-2 list data, and emits one normalized public `schema_version: 1` document for JSON success, refusal, partial completion, or failure. Target resolution keeps local-over-remote and branch-over-path precedence, refuses duplicate remote-only names, and leaves shortcut/PR/MR/URL handling to Worktrunk. Before copy, setup, or tmux mutation it requires an exact canonical registered Git worktree in the invoking repository's primary checkout or `.worktrees/` root, with matching common/private Git dirs, local ref, branch, HEAD, and backend identity. The repository lock is acquired before switch/create; classification is refreshed under that lock; the per-worktree lock then joins the same lease through synchronous `copy-ignored`, blocking `dev:setup`, and deterministic `ftm`, whose JSON is normalized into the public result. `prune` accepts only clean local linked worktrees reported `integrated` or `empty`, refuses main/current/ambiguous targets, removes the matching tmux session before calling foreground Worktrunk removal, validates Worktrunk 0.76.0's one-element removal array, and verifies the path, registration, local branch, and unchanged remote-tracking refs. Later failure returns `partial` and never retries with force; when the worktree survives after its session was removed, explicit `wt repair TARGET` recreates the canonical session. Worktrunk is pinned in `config/mise/config.toml` with global `pin = true`; the deliberately removed global mise lockfile stays removed, so runtime executable/version verification and adapter fixtures are the safety boundary. `config/worktrunk/config.toml` pins list schema 2.

## Fish shell helpers

Fish carries repo workflow helpers and desktop integration environment variables.

Fish config is fully mise-owned: `~/.config/fish` is a mise `[dotfiles]` symlink to `config/fish/` (`config.fish`, `conf.d/*.fish`, `functions/*.fish`, `interactive/*.fish`). The HM fish and bash modules are removed; fish plugins (autopair, nix-env, done) went with them by design — the mise port is plugin-free. Nix-specific PATH setup (`~/.nix-profile/bin`, per-user profile) lives in the committed fragment `mise/fragments/fish/nix.fish`, linked to `~/.local/share/fish/nix.fish` via `[dotfiles]` and sourced by `conf.d/env.fish` when present; `conf.d/00-path.fish` bootstraps portable paths. The mise tree activates mise from `config/fish/conf.d/mise.fish` and keeps fish-only aliases in `config/fish/interactive/aliases.fish`; shared shell aliases live only in `config/mise/config.toml` `[shell_alias]` now that the nix mise `globalConfig` duplicate is gone. `config/mise/config.toml` also links `~/.profile`, `~/.bashrc`, `~/.bash_profile`, `~/.zshrc`, and `~/.zprofile` from `config/bash/` and `config/zsh/` so bash/zsh get the same mise hook plus upstream Worktrunk init.

Prompt/tool hooks all live in `conf.d/`: `starship.fish`, `fzf.fish` (exports `FZF_DEFAULT_OPTS`/commands), `zoxide.fish`, `atuin.fish`, and `direnv.fish`; the HM starship/fzf/zoxide/direnv modules are removed. The login shell is `/opt/homebrew/bin/fish` (brew formula; nix-darwin fish is removed). Fish fzf Ctrl-T uses fzf's fish token parser, so the current path token becomes `$dir` and `conf.d/fzf.fish` passes `$dir` as fd's explicit search path. Fish defines a `jj` wrapper that runs real `jj` inside jj repos, allows `jj git init`, and falls back to `git` with a hint in plain git repos. `PLUG_EDITOR` is exported as a `hammerspoon://nvim-open` URL so stack-trace links delegate final Neovim target resolution to Hammerspoon.

Fish sources `conf.d/usage.fish` to run jdx/usage `completion-init` for fish, which scans `$PATH` once per interactive shell and registers completions for executable scripts whose first line is a `usage` shebang. The sourced init is patched with a readable-file guard so unreadable system executables do not print startup warnings.

Fish owns the Worktrunk integration locally instead of upstream's `wt config shell init fish` (the HM worktrunk program module is removed — wave-1 mise flip — so no upstream shell init is enabled anywhere; the `wt` binary comes from mise `[tools]`). The local `wt` function in `functions/wt.fish` is thin glue around the shell-agnostic `~/.dotfiles/bin/wt`: it passes `WT_SHELL=fish` plus `WT_CD_FILE`/`WT_ENV_FILE`/`WT_EXEC_FILE` temp paths, then cds to the cd file's target, sources the env file (`GIT_WORKTREE` set/unset), and evals any exec file — the things a child process cannot do to its parent shell. The zsh twin in `config/zsh/zshrc` does the same with posix syntax. All wt logic lives in the wrapper script (see User bin scripts). mise `[dotfiles]` links `~/.config/worktrunk/config.toml` from `config/worktrunk/config.toml` (`worktree-path = "{{ repo_path }}/.worktrees/{{ branch | sanitize }}"`), keeping new worktrees under the repo. Completions in `interactive/completions.fish` complete v2 verbs, worktree branches from `wt list --json`, and `window`/`session`/`cd` for `-t/--target`. `conf.d/wt-auto-prune.fish` is inert (the wrapper's detached auto-prune that fed its note file is deleted) and pending removal with the rest of the shell-glue trim. Ghostty fish integration is not sourced here; Ghostty handles it itself.

## User bin scripts

User scripts in `bin/` provide repo workflow shortcuts. Both systems source `~/bin` from `~/.dotfiles/bin`: Home Manager through its generation and mise through a direct directory link. Mise uses `symlink-each` only for mutable `~/.local/bin`.

`fancy_numbers` is a POSIX `sh` helper that preserves non-digits and renders digits as superscript glyphs by default, or subscript glyphs with `-v sub`/`--variant sub`; tmux and Starship prompt count renderers call it. The `starship` wrapper preserves the real Starship CLI behavior while exporting `STARSHIP_JOBS_COUNT` from `starship prompt --jobs …` so the custom jobs module can render that count through `fancy_numbers`.

The `m` script wraps common Mix/Phoenix commands. Its `m s` Phoenix server command always starts a named IEx node: an explicit argument is used as-is; without an argument, the name is derived from the current directory basename, or from the main checkout basename plus linked-worktree directory basename when inside a Git worktree. Derived names are lowercased and use dashes unless the source name already uses underscores.

`bin/wt` is the shell-agnostic wrapper core: `wt id [path]` prints the `{repo}-{branch-slug}` `GIT_WORKTREE` id (single source of truth, consumed by project mise stubs), the v2 dispatch (implicit targets, `-t` flags, `ensure|new|open|path|repair|prune`, `list --json`) sources `bin/wt-lock-lib` + `bin/wt-v2-lib`, and every other invocation execs the mise-pinned Worktrunk backend untouched as the upstream escape hatch (resolved via the same `v2_resolve_backend` recursion/version checks, exit 127 when unresolvable). `write_env`/`emit_cd` write the per-shell env/cd files for the fish/zsh glue; without a wrapper the script prints the worktree path instead of cd-ing. The legacy target-mode scripts (`wt-tmux-target`, `wt-tail-logs`) and the generic `tmux-kill-session`/`tmux-services` helpers are deleted — `ftm` owns all tmux lifecycle.

## Tmux layouts

Mise owns tmux and its configuration on both hosts.

`config/mise/config.toml` declares `tmux = "latest"` and `[dotfiles]` links `~/.config/tmux` to sole source `config/tmux/`. `[env]` keeps `TMUX_LAYOUTS` at `~/.config/tmux/layouts` and the TPM paths at `~/.local/share/tmux/plugins`. Existing servers keep their original executable until restarted; new servers use the active mise version.

`tmux.conf` uses one `terminal-features` entry for standard xterm capabilities (`RGB`, clipboard, strikethrough, underscore style/colour, and extended keys). Tmux reads italics and cursor-style capabilities from terminfo/default features, so no raw `terminal-overrides` are needed. Server-scoped extended-key options emit CSI u. The removed `xterm-keys` setting was a no-op in tmux 3.7, and `aggressive-resize` had no effect with `window-size latest`. Shell-bound prompt/session values use tmux's `q` format modifier before reaching `run-shell`.

Tmux layout scripts are Bash-compatible session builders discovered by `ftm` from `TMUX_LAYOUTS`. `prefix+C-p` toggles an interactive shell popup at the bottom center, 60% wide by 35% high, without changing pane topology; `prefix+p` remains unbound. `bin/tmux-popup-shell` canonicalizes the invoking pane's current directory and attaches the popup to a hashed session on a private tmux server, so each CWD gets one shell whose process, directory changes, and terminal state survive popup closure. Inside the popup, `prefix+C-p` detaches its private tmux client and closes the popup; `prefix+C-space` closes it and replays the outer `prefix+C-space` binding to open `ftm`.

`bin/tmux-process-name` renders automatic window names and pane titles as `<icon> <name>` (adapted from nicknisi's `tmux-smart-name`/`nerdwin`, minus Claude handling). `tmux.conf` passes `#{pane_current_command}`, `#{pane_current_path}`, and `#{pane_tty}` so ps is skipped in the common case; a `node` command is re-identified as pi via `ps -t <tty> -o comm=` matching the `pi` process title; ssh panes keep `ssh:host` naming with foreground (STAT `+`) detection; paths under `<project>/.worktrees/<wt>` render as `project (branch)` (branch falls back to the worktree dir name). A legacy single-tty-arg form keeps live servers sane until config reload. Windows explicitly named by layouts have `automatic-rename` off and are unaffected. The Hammerspoon title parser only reads the `session:window:pane:pid` prefix, so the richer trailing name is compatible.

The `bin/ftm` picker pins running sessions first: MRU-running entries, then remaining sessions by tmux `session_last_attached`. A dim all-dash divider row (sized to the list via `FZF_COLUMNS` on reload, estimated from the tmux client width otherwise) separates them from dead MRU entries, zoxide dirs (default 10, `FTM_ZOXIDE_LIMIT`), and remaining layouts. Enter/Alt-Enter on the divider are no-ops: both binds are nested fzf `transform` actions whose outer command is placeholder-free (it checks `$FZF_MATCH_COUNT`, with `\{}` escaped) because fzf skips any action whose template contains a bare `{}` when nothing matches — a bare-`{}` divider check made Enter a dead key for typed queries with no matching row (e.g. a dir known to zoxide but below the top-10 cutoff). With zero matches the outer transform emits `print-query` directly; otherwise it emits an inner `{}` transform that emits `ignore` on the all-dash divider (picker stays open) and `replace-query+print-query` elsewhere; `try_session` keeps an all-dash backstop check. Alt-Enter's fresh path uses `accept` instead of `print-query` because `print()` mimics `--expect` (output order: query, marker, selection) and `print-query` drops queued `print()` lines entirely; `try_session` therefore scans every output line — marker honored anywhere, first non-marker line wins — and the fzf call has no `--exit-0`, so a completely empty list still opens the picker for typed-query creation (the no-match `accept` exit code 1 is swallowed with `|| true` under `set -e`). Displayed `~` shortening uses a `$TILDE` variable replacement, not `\~`, because bash 3.2 keeps the backslash (which then breaks `try_session`'s `~` re-expansion of `name<TAB>path` rows); `try_session` also strips a leading backslash before expanding. MRU state lives at `${XDG_STATE_HOME:-~/.local/state}/ftm/recent` and is bumped on every switch/create. Lines are `name<TAB>cwd`, so an entry whose session died but whose dir still exists keeps rendering with its path. The MRU write and post-switch hook launch happen before `switch-client`, because the `C-Space` popup collapses and tmux HUPs the script after switching; post-switch therefore runs detached (`nohup`). Zoxide entries render as `name<TAB>dimmed path` and dedupe by name. A running session wins on selection; on creation, a cwd that is a linked Git worktree routes through the deterministic worktree builder under its canonical `{repo}-{branch-slug}` name (`worktree_session_for` → self-invoked `ftm ensure --kind worktree`, with inherited `GIT_WORKTREE` cleared before `wt id`), so picker/zoxide entry points converge with `wt`; otherwise normal Enter restores an available ftm snapshot before named layouts. Alt-Enter bypasses worktree routing, snapshots, and named layouts; non-layout creation (fresh or plain) builds through ftm's own canonical generic builder (`ftm ensure --kind generic` — code/agent/services), falling back to a plain `tmux new-session` (the former `layouts/default.sh` is deleted).

The picker shows an fzf preview (below the list, 65%, toggle with `?`, scroll with `ctrl-u`/`ctrl-d`). The fzf call passes `--height=100%` because the interactive shell exports `FZF_DEFAULT_OPTS` with `--height=25%`, which would otherwise shrink the picker to a quarter of the popup. Running sessions invoke the dependency-free Bun helper `bin/ftm-grid-preview`, which renders one bordered card per live Pi agent in an aspect-scored grid sized to `$FZF_PREVIEW_COLUMNS` by `$FZF_PREVIEW_LINES`; sessions without a Pi agent show their active pane. `pi_panes_for` scans manifest JSON under `$PI_STATE_DIR/manifests/*.info` (socket basenames may be shortened and hashed), rejects records marked `ephemeral`, selects records by their `session` field, unions them with status files, then validates each pid, pane, and `pi` process title through `is_pi_pane` (`ps -t <tty> -o comm=`). The helper polls each target with `capture-pane -e -p -S -200` every 500 ms, removes trailing blank viewport lines, keeps the newest lines that fit each card, and preserves only safe SGR styling. It emits complete newline-delimited frames and uses `CSI 2 J` only when content changes, matching fzf's streaming-preview protocol without raw mode, alternate screens, or cursor positioning. Pi exposes no message-history query over its active socket bridge, so the rendered Pi TUI panes remain the preview of recent Pi messages. Dir entries preview their path; layout entries preview the script; unknown names preview nothing. The `C-Space` popup binding is sized `70%`×`75%` to fit the bottom preview (`config/tmux/tmux.conf`), and direct `ftm` invocations use `fzf --tmux center,70%,75%`.

Running-session rows render bold; non-running entries (layouts, MRU dirs, zoxide dirs) render dim — there is no `*` marker. Running rows also carry a pi status icon using the common three-state agent model (workmux/fleet/claude-squad): red `●` needs attention — blocked on a structured `ask_user_question` or turn ended with an error (states `asking`/`error`); green `●` actively working (state `working`); white outline `○` idle — no prompt yet or turn completed cleanly (states `idle`/`done`). Sessions without a live pi status file render no icon. States come from the `agent-status.ts` pi extension's files (`$PI_STATE_DIR/status/pi-{session}-{window}.status`, line `state pid session`); `print_list` reads that directory once and validates pids with `kill -0` — no sockets or pane captures, so the picker opens instantly and stale files from crashed pis are ignored. Prose questions at turn end are caught by `agent-status.ts`'s trailing-`?` heuristic on the final assistant message and render red `●` (state `asking`). `strip_markers` and the kill/rename sed patterns strip both icons (fzf's `--ansi` already strips the bold/dim styling before selections reach them).

`ftm` stores versioned, base64-safe per-session snapshots under `${XDG_STATE_HOME:-~/.local/state}/ftm/snapshots/<name>`. Each atomic snapshot records session path, window names/indexes/layouts/focus/zoom, pane indexes/cwds/foreground commands/focus, and Pi's `@pi_session_id`; Pi panes restore as `pi --session <uuid>`. `ftm remove` snapshots before killing (both the `prefix+C-k` binding and the picker's ctrl-k call it). The global tmux `session-closed` hook calls `$HOME/.local/bin/ftm --snapshot-all` to refresh surviving sessions; tmux has already discarded the closed session then, so the pre-kill path owns its final capture. The former `$TMUX_HOOKS` event-hook API (`pre-create`/`post-create`/`post-switch`) is removed — it never had an enabled consumer; project lifecycle behavior belongs to mise tasks.

Scripts use `.sh` names and `#!/usr/bin/env bash` so they run through bash regardless of the interactive shell. Fixed canonical layouts set explicit roots: `mega` in `/Users/seth/.dotfiles`, `rx` in `/Users/seth/code/work/strive/rx`, and `verify-doctor` in `/Users/seth/code/work/strive/verify-doctor`. Generic layouts may resolve through zoxide and fall back to `$HOME/code`. Agent windows launch plain `pi`; active tmux config has no pinvim/pimux launch, hook, status command, or key binding, and `ftm` has no Ctrl+V pimux action or socket marker. The status bar avoids visible `#()` jobs entirely: tmux force-restarts every `#()` job at each `status-interval` tick, and slow jobs (multiple `tmux show-option` roundtrips, `pmset`, the `dnd` Shortcuts automation) render as blank segments until they complete — the top-bar flicker. `bin/tmux-status-updater` runs as the single zero-output `#()` in `status-right` (invisible while restarting) and stores battery (one `pmset` parse honoring the `@batt_*` options from `plugins.tmux.conf`, replacing the tmux-battery plugin's `#{battery_*}` interpolation), DND, and UTC-clock values in `@status_*` options, overwriting only on success so failures keep last-good values. Visible segments in `megaforest.tmux.conf` are pure `#{@status_*}` format reads plus native strftime `%H:%M` for local (Eastern) time; they expand in-process and cannot blank. `status-interval` is 15s. tmux-continuum's injected zero-output save-check `#()` also remains. Status-left's mode-indicator `#()` jobs were left untouched.

## Tmux plugins

`config/tmux/plugins.tmux.conf` is TPM-managed. Mutable plugin checkouts stay under `~/.local/share/tmux/plugins`.

TPM installs `abhinav/tmux-fastcopy`. Prefix+C-f labels URL and path targets. A regular hint runs `bin/tmux-copy`, which trims only outer whitespace and writes the result to the macOS clipboard. A shifted hint runs `bin/tmux-open-things`: any `scheme://` target opens unchanged, bare domains use HTTPS, and bare localhost/IP targets use HTTP. Existing directories open in Finder. Files open in a new Neovim window in the same tmux session; the window starts in the file's directory and honors trailing `:line[:column]` positions. The action creates the editor window and exits instead of running Neovim inside fastcopy's swapped pane.

The fastcopy URL matcher accepts arbitrary URI schemes and bare domains, localhost names, IPv4 addresses, and bracketed IPv6 addresses, each with optional ports and URL suffixes. Its path matcher accepts absolute, home-relative, and relative paths with one or more segments. Both matchers accept soft-wrapped targets. `and-rs/flash.tmux` (TPM-managed, prebuilt Zig binary fetched by its entry script) replaces `tmux-easymotion` and the abandoned flash-copy experiment: prefix+C-s (or `s` in copy-mode-vi) opens a replica-pane overlay and jumping moves the copy-mode cursor. Its pane capture travels over `capture-pane` stdout, so large Pi captures cannot trigger tmux's `command too long` limit that broke `kristijan/flash-copy.tmux` (v1.6.1 passes the full ANSI capture as a `set-buffer` argv argument; a stdin `load-buffer` patch fixed it, but the plugin was dropped as copy-only overlap with fastcopy).

Tmux-resurrect and tmux-continuum provide whole-server crash recovery alongside ftm's per-session snapshots. Continuum saves every 15 minutes through its `status-right` hook and restores once at server start. Resurrect uses prefix+S/R, captures pane contents, restores Pi processes selected by `@resurrect-processes 'pi'`, and runs the custom `pi_session` save strategy from `bin/tmux-resurrect-save-pi`; tagged panes become `pi --session <uuid>`, with `pi -c` only for untagged Pi panes. Neovim uses resurrect's `session` strategy, which runs `nvim -S` when the pane cwd contains `Session.vim`.

Fleet is installed by mise from `github:nicknisi/fleet`. `tmux.conf` binds prefix+f to `$(mise where github:nicknisi/fleet)/fleet sidebar --from '#{pane_id}'`, matching Nick Nisi's sidebar toggle and ensuring the split opens in the current tmux window when multiple clients exist.

`tmux-mega-fingers` is currently disabled but remains a separate OSS checkout at `~/code/oss/tmux-mega-fingers/` (fork of `artemave/tmux_super_fingers` @ `523dc9b`; see that repo's `UPSTREAM.md`). Fork additions over upstream:

- Inside fingers mode, a shifted hint letter (e.g. `A` vs `a`) selects the copy (secondary) action for that one selection; lowercase selects open (primary). Single `@mega-fingers-key` entry (`C-f`). Upstream's `space` sticky-toggle is kept.
- New finders registered in `tmux_mega_fingers/finders/__init__.py` after the path/url/rails finders so real paths win overlap resolution: `git_sha_finder` (git/jj hashes, copy; excludes diff `index <hex>..<hex>` blobs), `email_finder` (copy / `mailto:` open), `github_ref_finder` (`owner/repo#123`, bare `#123` resolved against the pane cwd's origin remote, and dot-less `owner/repo`; defers to `FilePathFinder` when the slug is an existing local path).
- `_remove_overlapping_marks` is implemented (was a no-op TODO): drops marks that overlap an earlier finder-order mark, so e.g. a github slug inside a full URL or colliding with a file path is suppressed.
- `pi_section_finder` exists but is disabled (not registered); its on-screen markers are unconfirmed — tune `PI_SECTION_PATTERNS` and add it to `FINDERS` once known. (True multi-line section spans need an architecture extension beyond the single-line finder API.)

The disabled `tmux-mega-fingers` fork captures panes with `capture-pane -J`, so its finders do not need fastcopy's explicit soft-wrap patterns.

## Tmux golden layout

`config/tmux/plugins/tmux-golden-layout/` is a local, dotfiles-owned tmux layout manager (TypeScript on Bun, TPM-compatible structure) that golden-ratio-resizes the focused pane and exposes a declarative per-window layout API.

`plugins.tmux.conf` loads it with a direct `run-shell .../golden-layout.tmux` instead of a TPM `@plugin` entry so prefix+U can never `git pull` the dotfiles checkout and prefix+M-u can never delete it. The entrypoint records the active resume binding in `@gl-bound-resume-key`, removes the old binding when `@gl-resume-key` changes, and unregisters its hooks, binding, and cached Bun path when disabled or when Bun is unavailable.

Behavior: every window resizes the focused pane to exactly `1/phi` of the window on each axis with siblings, parsing and rebuilding the complete `#{window_layout}` string (dimensions, coordinates, separators, checksum) and applying it with one `select-layout`. Unfocused branches split the remainder by leaf count; nested unfocused groups equalize. All computations restart from exact values (1/phi, declared ratios, or the immutable manual reference), so outer-window resize cycles are drift-free. A manual resize or foreign `select-layout` pauses that window and shows `Auto resize paused for this window; prefix+= to resume`; prefix+= resumes and reapplies. Zoomed windows defer changes until unzoom. Tmux 3.7 cannot restore custom layouts containing floating panes, so the plugin preserves declarations and manual references while a floating pane exists and applies pending work after it closes. Per-window state lives in window-scoped `@gl_*` user options keyed by stable window id (auto-cleaned when the window dies). Loop prevention uses short-TTL, layout-keyed `@gl_history_<hash>` options, so concurrent applies cannot overwrite each other's echo guards. Hooks pass their originating layout and focus pane. Hook and API transitions share a per-socket, per-window FIFO lock made from unique PID/timestamp/token contender files; dead owners recover immediately, live contenders expire after 10 seconds, and the last process removes empty lock directories. Tmux subprocesses time out after 3 seconds, before stale-lock recovery. Every apply re-fetches state first and makes one post-apply settling pass if focus or dimensions changed. Debug logs go to `$TMPDIR/tmux-gl-<uid>/` when `@gl-debug` is on. Hooks are indexed at slot 188 (`after-select-pane`, `after-split-window`, `after-resize-pane`, `window-layout-changed`, `window-resized`), all `run-shell -b`; the entrypoint is idempotent on reload.

The declarative API (`bin/gl declare|grid|clear|apply|pause|resume|companion|status`) lets Nvim/Pi declare per-window topologies with exact ratios and ordered stable pane ids (e.g. Nvim/Pi 65/35, Pi+subagents 50/50 nested grid); declarations suppress golden resizing while present and reorder panes with `swap-pane` when needed (tmux maps layout leaves to panes by window order, not by the ids in the string). The CLI rejects malformed objects, pane ids, split axes, ratio arrays, nonfinite ratios, duplicate panes, and pane-set mismatches. Allocation rejects invalid totals/minimums and treats zero, negative, or nonfinite weights as zero while preserving the exact cell total. The pi-interactive-subagents fork that will call this API is future work; until then its 120 ms `even-horizontal` rebalance simply pauses the affected window. Tests: `bun test` in the plugin dir runs unit and isolated-server integration coverage, including concurrent/crashed locks, disabled reloads without Bun, focus/apply races, floating/zoom deferral, declarations, and loop prevention.
